# 第11批：本机PDF信息解析与自动填写

按用户确认完成“第一步”：选择PDF后由本机后端解析候选信息，补填空白字段，再由用户核对提交。当前69个端点，新增U13 POST /api/v1/papers/metadata/parse；Java运行依赖及数据库SQL未修改。

## 使用

打开http://localhost:5173，用户登录后进入“上传论文”，选择PDF即可。识别范围为题目、作者、摘要、关键词、DOI、发表年份和期刊；实际能否提取取决于文件中的信息和版式。页面显示已填写字段及核对提示，可重新识别或跳过。分类、标签、私有/共享和版权确认仍由用户选择。

本机解析上限20MiB，读取元信息及前3页文字；正式上传仍支持100MiB。大文件可手动填写。扫描件只提示需要OCR，暂不执行OCR、外部AI或DOI联网补全，也不请求PDF中的链接。

解析不创建论文、收藏、阅读、笔记或审核记录。点击正式提交才走原U7上传，重新校验PDF、字段、权限、版权及查重。解析失败不能绕过文件本身损坏或加密的校验。

## 自动填写行为

- 当前已有内容优先保留，识别等待期间新输入的内容也保留；仅将非空识别结果填入空白字段。
- 重新识别同一个文件仅补空值，失败时保留之前已识别及手工修改的内容。
- 更换或移除文件时，清除该文件自动填写且未修改的值；保留手工编辑。旧文件或已卸载页面的迟到响应不能写回。
- 标题支持原API规定的255字符；摘要去掉Mock时期600字符限制，按后端60000 UTF-8字节校验，自动摘要最多15000个Java字符。
- 上传及后续论文编辑中的作者、关键词均使用逗号、顿号或分号分隔，不按空格拆分，保留John Smith及deep learning等完整内容。识别年份不在默认下拉范围时也能显示。

## 识别方式及限制

复用PDFBox 2.0.35读取文档Title/Author/Keywords；明显的Word、Untitled、软件名或文件名模板不作有效标题。正文按位置排序，依据首页字号与相邻行推测标题和作者，依据Abstract/摘要、Keywords/关键词等标记确定字段。优先使用明确标记的期刊和出版年份，不把PDF创建时间或Received年份当发表年份。参考文献区不用于获取论文DOI，首页明确DOI脚注可补充识别。

响应返回各字段、pageCount、parsedPages、sources（metadata/text）及warnings。没有证据的字段留空，不能将启发式结果当作准确识别承诺；复杂双栏、特殊字体、异常编码及多语言版式仍可能需人工修正。当前测试使用自建PDF，尚未用用户实际论文集合评估准确率。

最多2个实际解析任务，名额在工作结束清理后释放；请求等待20秒超时不会提前释放后台任务名额。文字提取检查10秒协作截止及80000字符限制。PDF加载内部并不保证可立即中断，因此20秒是调用方等待上限，超时任务仍可能占用名额；这不是操作系统级CPU/堆内存隔离。PDFBox使用私有.scratch缓存，文档关闭后清理；不存储上传PDF为业务文件，不暴露临时路径，不记录正文或作者等解析内容到操作日志。接口要求有效登录，普通用户与管理员均只能解析本次提供的文件。
