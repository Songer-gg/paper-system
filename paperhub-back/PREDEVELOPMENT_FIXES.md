## 验证结果

- `paperhub-frontend`：`npm run build`通过（包含vue-tsc）；`eslint src --no-fix`通过。仍有Element Plus/ECharts大包提示，不影响构建。
- API：TypeScript契约编译通过。
- `node paperhub-api/tests/contracts.cjs`通过：HTTP方法、JSON part、日期适配、版权实际值、JSON/PDF失败处理、用户隔离、撤回禁止恢复、删除保留笔记及敏感读取日志。
- 本地MySQL 8.0.43：独立临时数据目录和随机端口，核对`@@datadir`后才执行SQL；建表、种子及26项约束检查通过，含两个独立连接并发共享去重。
- 实测修复了生成列基列与CASCADE外键不兼容的问题，分类树删除采用Service授权后从叶到根执行，数据库用RESTRICT兜底。
- `git diff --check`通过。没有提交或推送Git变更。

## 仍需后端实现的能力

这些属于后端开发交付项，不能把本轮契约修复当作服务已经存在：

1. 真正的JWT签发/撤销、角色与账号状态校验、跨用户鉴权、敏感读取的可靠审计。
2. Service事务、并发状态转换、真正PDF存储/服务端解析与清理补偿。
3. Service到ApiClient的正式接入、真实PDF渲染与下载、登录token持久化及过期处理。前端继续使用Mock演示，模拟页数不作为后端元数据。
4. Maven依赖实际解析、Java 8运行、集成测试、安全扫描及部署。
5. 若已有部署数据库，先单独备份、审计并编写增量迁移；本轮新空库结构不直接应用于存量数据库。
